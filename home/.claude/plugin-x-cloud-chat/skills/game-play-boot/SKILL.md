# game-play-boot — open a game thread

boot opens a thread, `game-play-fold` ends it. his rules behind each step: memory `thread-opener`, `games-inbox-outbox`, `fold-protocol`, `thread-names`. this skill is the order.

## 1. the mac, before anything else

- the remote-devices `start_process` tool missing → `connect_device` (purpose `run`), end the turn; research waits for the link
- on link: `zsh -lc 'echo mac-ok'` through it. which desktop commander counts: `firelink`'s lane line
- 📌 `connect_device` can say «connected» while the tools stay gone → one line asking him to quit and reopen the Claude desktop app
- then load `firelink`

## 2. read the game's state

- `/mnt/project-files/games/<game>/index.md`, «▶ next» first, then `corrections.md`; his reports there beat every other file
- his doc `dima-<game>` (url in `index.md` 🪪 identity): list its tabs, read each one; a `<highlight>` marks what matters to him
- no folder yet → the game is unseeded: `game-seed`, not this skill

## 3. sweep, all at once

- his doc's 📬 q&a tab: every ❓ with no 💬 under it
- open comments on every tab: one `query` per tab body, in parallel; open = a root comment with no resolve and no Claude reply
- `dima-games-inbox` (https://claude.ai/artifact/5FZ3c1uru2k416eYR3kqcy): this game's items and «any game» items; other games' stay
- cluster everything into one plan, answer in one pass: a question → 💬 under its ❓ in the q&a tab, a wish → his doc in place, each item once, cross-linked; then delete the swept items from the inbox
- 📌 answered q&a pairs are his to clear, and his ✍🏼 to-do list in 🚀 main is never touched
- trophy or progress numbers in any answer → the `firelink` tracker first

## 4. the opener reply

- first line: his doc link; `attached_outputs` = his doc + the inbox (kind `link`), plus any extra doc his `index.md` 📂 files lists
- then: whether the mac link works, where he is («▶ next»), what the sweep answered
- the thread name per memory `thread-names`: `🎮 <game> ✦ N`, N = the last session + 1
