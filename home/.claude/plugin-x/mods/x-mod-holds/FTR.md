# x-mod-holds — features

- 🧭 asked, not built yet (a new ask, an experiment) · ⬜ built, not checked yet · 🐞 built, its check fails · ✅ passes in the app's verify recipe · 🔎 dima used it and it holds
- given/when/then lines are sixth sense's exit lines
- makes: lines name what a feature leaves behind — a file, a take, a clipboard item
- decision: lines record a choice and its reason

no two sessions write the same file git can commit: a session's first edit of a file holds it until the file is committed, the session ends or it sits idle 30 min; a file outside a repo, or one git ignores, reads clean and is never held (a commit is how a hold ends, and such a file has none). nothing draws the holds: the refusal names the holder (x-mod-stash's 🔒 chip left in FRM-354).

## edits

two sessions, A and B, in one checkout.

- ✅ holds run in a Code-tab session
  - given a Code-tab session
  - when holds checks a file's git state
  - then the check returns; if it cannot, the build stops before any other line
  - proven live by clio, 2026-10-04: a `--bg` session held `.holds-probe.txt`, a Code-tab Write of the same path was refused «held by session 75f531d4, which took it 2 min ago» — a deny means the git check through `$.process` returned, since fail-open would have let it through
- ✅ a first edit takes the hold
  - given A edited `x.ts`
  - when B edits `x.ts`
  - then B is refused, and the message names A and when A took the hold
  - decision: no override in v0 — the deny names who to ask; dima's tick is the one door since FRM-544 slice 2d (the pass, below)
  - decision: the holder is named by the first 8 characters of its session id; every session in one checkout shares the repo name
  - decision: the hold keeps the real path in its own case and git runs on it, so a symlinked leaf (`~/.claude/CLAUDE.md`) is held like its target
  - decision: the key is lowercased on every platform — APFS is case-insensitive and a mod cannot ask which os it runs on
  - proof: tests/holds.test.ts::a first edit takes the hold
- ✅ dima's tick passes a held file for the asking session (FRM-544 slice 2d)
  - makes: a `pass:<B>:<path>` key in this store, and a `passed:<A>:<B>:<path>` line for the holder
  - given A holds `x.ts` and B's refused edit raised an ask quoting `/repo/x.ts` in one backtick span (`~/…` and a linked folder resolve)
  - when dima ticks it, in orbit or on x-herdr-deck, within 2 h
  - then B's edits of `x.ts` go through until B's next commit through Bash or its turn's end, and B takes no hold of its own
  - then A's next prompt carries one line naming B and the file; the hold stays A's for every other session
  - then the tick is spent: after the pass ends, B is refused again until a new tick; a tick quoting another file, or only prose, older than 2 h or stamped ahead of now opens nothing
  - decision: a pass, never a hand-over — the file stays A's, so A's commit still releases it and C still meets A's name
  - proof: tests/holds.test.ts::a tick quoting the held file lets the asking session write it; a pass takes no hold: the file stays the holder’s for every other session; the holder hears of the pass once, at its next prompt; the pass ends with the asking session’s turn, and the spent tick opens no new one; the pass ends at the asking session’s commit through Bash; the hold refuses the asking session on …; a tick quoting the file through a linked folder passes it; a tick quoting the file from ~ passes it
- ✅ an edit refused beneath the holds, or one the tool errored on, leaves no hold (FRM-428, PK-264; FRM-472 07c)
  - given A's first edit of `x.ts` is refused by a hook beneath (x-mod-guard) or errors (cc's own refusal, an `old_string` not found)
  - when B edits `x.ts`
  - then the edit goes through; a hold A's earlier edit landed stays held
  - proof: tests/holds.test.ts::an edit refused beneath the holds leaves no hold; a refused edit keeps the hold an earlier edit landed; an edit that errored leaves no hold; an errored edit keeps the hold an earlier edit landed
- ✅ the holder keeps editing
  - given A holds `x.ts`
  - when A edits it again
  - then the edit goes through
- ✅ other files stay free
  - given A holds `x.ts`
  - when B edits `y.ts`
  - then the edit goes through
  - proof: tests/holds.test.ts::other files stay free
- ✅ a commit releases
  - given A committed `x.ts`
  - when B edits it
  - then the edit goes through and A's hold is gone
  - decision: clean releases only a hold whose edit landed — while A's permission prompt is open the file is clean and still A's
  - and a commit run through Bash releases at once, `git -C <dir>`, `git -c <k=v>` and `git --no-pager` ahead of `commit` included (H5)
  - proof: tests/holds.test.ts::a commit releases the holder's file; tests/holds.test.ts::a commit through Bash releases the clean holds before the turn ends; tests/holds.test.ts::a commit behind git's own options releases the clean holds too (H5)
- ✅ a commit through Bash releases at once
  - given A holds `x.ts` and commits it through Bash (`x lane commit …`, `git commit …`) mid-turn
  - then A's clean holds drop from the store right after the command, so B's edit goes through; a command that commits nothing keeps them to the turn's end (FRM-337)
  - decision: before, a hold dropped only at A's turn end or on B's next try — a coordinator in one long turn kept its holds ~30 min past the commit and blocked FRM-336's codie
  - proof: tests/holds.test.ts::a commit through Bash releases the clean holds before the turn ends; tests/holds.test.ts::a commit behind git's own options releases the clean holds too (H5); tests/holds.test.ts::a Bash command that commits nothing keeps the holds until the turn ends
- ✅ a new file stays held until committed
  - given A created a new file and left it uncommitted
  - when B edits it
  - then B is refused
  - proof: tests/holds.test.ts::a new file stays held until committed
- ✅ a dead holder releases
  - given A's process was killed
  - when B edits A's file
  - then the edit goes through
  - decision: the pid is the `$PPID` a mod's child sees (measured: the `claude` process), kept with its start time, so a reused pid reads as dead
  - proof: tests/holds.test.ts::a dead holder releases
- ✅ an idle holder releases
  - given A's last turn ended over 30 minutes ago
  - when B edits A's file
  - then the edit goes through
  - decision: 30 min — prior art ranged 5–120, and 5 min dropped long turns
  - proof: tests/holds.test.ts::a holder idle for 30 min releases; tests/holds.test.ts::a holder idle under 30 min keeps the hold
- ✅ one winner in a race
  - given A and B edit the same new file in the same second
  - then never both of them hold it
  - decision: no compare-and-set, so after its write a claim that sees any rival yields; a true tie refuses both and the next try settles it — earliest `at` let both win when one session's write landed late (sixth sense round 1)
  - proof: tests/holds.test.ts::one winner when two sessions take a new file in the same second; tests/holds.test.ts::one winner when a rival writes while the claim is in flight
- ✅ a broken store never blocks work
  - given the store file is unreadable
  - when B edits
  - then the edit goes through and the error is logged
  - proof: tests/holds.test.ts::a broken store never blocks an edit
- ✅ a whole-tree `git stash` over a held file is refused — by x-mod-guard, which reads this store; its `FTR.md`, «held files»; a Bash write to a held file runs since FRM-581
  - proof: x-mod-guard/tests/stash.test.ts
