# x-mod-guard — features

- 🧭 asked, not built yet (a new ask, an experiment) · ⬜ built, not checked yet · 🐞 built, its check fails · ✅ passes in the app's verify recipe · 🔎 dima used it and it holds
- given/when/then lines are sixth sense's exit lines
- makes: lines name what a feature leaves behind — a file, a take, a clipboard item
- decision: lines record a choice and its reason

  - and wherever it sits: the one walker, `rules/command.ts`, reads it behind a wrapper (`sudo`, `env`, `timeout`, `xargs`, `pnpm exec`, `x as <member> --`, …), inside a shell keyword, a group, a function, a `$( … )`, a `sh -c` script, a heredoc or string fed to a shell, an `eval`, a git alias, a `find -exec`, its name held in a literal variable or split by quotes; every case is a row in `tests/escapes.ts`

  - then that one command is refused, the reason opening with «nothing in this command ran», then the door: `trash`, `claude stop <id>`, `git stash push -u -- <your paths>`, a run without the flag, `x lane rebase-main` for a force-push, «ask clio» where no safe door exists

  - then every other command runs: a sign, a body write, a merge-auto `--dima-ok`, a write to a shelf or store file, a plain push, an overwrite, a lint shape — no rule reads them any more

  - decision: quoted text and comments are never read as commands, and a heredoc body only when a shell consumes it — a commit message may name `rm -rf`
  - 📌 not read: a script piped into a shell from a file or the net, a script run by path, a name the shell builds at run time; the guard keeps out mistakes, never a determined script
  - 📌 known gap: a delete through a script language (`perl -e 'unlink …'`, `python3 -c 'os.remove(…)'`, `node -e 'fs.rmSync(…)'`) runs: the floor reads shell commands, never a program's calls (sixth sense on FRM-581, kept by clio's pick)
