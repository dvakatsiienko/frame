# usage pacing — the 5h window is watched every siesta, parallel lanes bend to it

dima, 2026-10-08 (boot line): «for 5h window — keep an eye on it and pace it in a way it does not overfill. keep it as perm habit … attention and wellbeing first, output volume after.»

- **the door depends on where the session was born**: desktop Code tab → `mcp__ccd_session_mgmt__get_usage` (plan windows + this context's size); a terminal → `shelf/cc-usage-window.json`, written by x-mod-stash on every `session.measure` (FRM-366; the desktop half is proven once its probe lands, until then `get_usage`). the boot names the door it uses.
- 🌤️ **a siesta fires `cclio:siesta`** — on a member's done report, a batch of mine touching 3+ files or any memory, rule or skill file, or dima's «siesta»; the skill holds the flow (dima, 2026-10-10)
- **read at every siesta and before every spawn**; the reply carries one line, only in the turn the read ran — `🔥 5h <used>% used | <pace>% pace | <delta>% spare ✅ (or debt ⚠️) | resets <hh:mm>` — his shape, `|` not `·`; «pace» is where the meter would sit at a one-to-one spend (elapsed share of the window), the delta is used − pace. pace = (now − (reset − 5h)) ÷ 5h; spare means spend more, debt means cool the lanes. dima, 2026-10-08: «if after 1 hour, 4 left, we are at 15 % — we have 5 % spare».
- **the shape to avoid**: stuck at 95 % of the 5h window with the reset 3h away. the plan spreads over the window that is left at boot, never over a fresh 5h.
- **over the line → pause the parallel lanes, never their cache**: a paused coder gets a one-line hold and a keep-hot ping before its 1h cache would cool; it resumes when the window loosens. the main lane keeps going at a chill pace.
- weekly: spend the window fully on the most needed work (dima leans to «spend it all + the weekly reset» over economic mode); going overboard is not waste, idling is.
