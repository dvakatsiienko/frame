# memory edits are announced, never silent

Adopted from Dima's inbox ask, option b of two he approved: **announce-always, gate-the-risky.**

- **every memory edit is named in the reply the same turn it happens** — file + one line on what
  changed. A silent memory edit is the failure this habit kills.
- **approval BEFORE the edit** for the risky class: deletions, rewrites of Dima's own words, and
  anything under `rules/` (fleet-wide blast radius).
- ordinary leaf tweaks and barrel line updates: edit, then announce — no round-trip.

## an edit is a groom, never a drop (dima, 2026-10-09)

«crew-* skills are crew members' DNA, the contract they function by»; the audit (`.scratch/retro-audit.md`) measured crew-coder 8.5k → 30.8k and craft-spawning 14.9k → 46.9k in 30 days with zero grooming commits.

- **add → read the whole file → groom**: every addition to a skill, rule or leaf reads the file it lands in end to end, merges the new line into what is there, and cuts what it outdates. the report names what got cut, or why nothing could be
- **a line enters a skill only** when it holds for every lane, no guard or test can enforce it, and it has no home yet; a one-lane stumble stays in its retro, an enforceable one becomes a guard or a test
- **retros fold when their lane ends**, in that turn; what is left at the halt goes through one gatherer subagent (issue type · count · paths · one quoted line per type), never 15 raw retros
- **at most 5 memory proposals per flush** reach dima; the rest print as counts
