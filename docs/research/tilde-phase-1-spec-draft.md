## FRM-504 — the mod counts a lane's rounds (chunk A)

wish: FRM-504 · size S

- read at the seal: which session sends `round N on <sha>` (`x:crew-codie` says codie), how a lane is named from a sender (glide's link keeps member names), and what `compact-carry.sh` prints today.
- a sender in no lane gets no count and no line.
- the count is the mod's own: one per distinct head sha in a `round N on <sha>` message; the N in the text is never read, so a compacted codie that restarts at `round 1` still counts up. it resets at the lane's next chunk (`next:`), never on a lower N.

exit lines:

1. given a codie linked to a lane, when it sends sixth sense its second `round N on <sha>` with a new sha, then that lane's count reads 2 and its turn carries no new line.
2. given the count reads 3, when codie sends a round message with a new sha, whatever its N, then its own next context carries one line naming the cap and that the stop goes to its coordinator; the message itself is delivered, nothing refused.
3. given a repeat for the same sha, a `round N` inside a quoted block, or the words «round two» in prose, then the count does not move.
4. given a session in no lane sends `round 2 on <sha>`, then nothing is counted and nothing is added.
5. given a lane's member is compacted, then its restored context names the lane's round count; red with the carry line reverted.
6. given a two-chunk lane, when the next chunk starts, then its count starts at 0, and the first chunk's count stays readable.
7. want line: feed rounds 1, 2, 3, compact, then `round 1 on <new sha>`: the stop line fires from the count alone; red on a hook mutated to read N from the text.

3. given a session crosses 55 % on any surface, then its next context carries one line that names 65 % as the upper boundary and says no rush; a second reading above 55 % adds no line; after its wind drops the fill, a new crossing adds one line.

8. given `pnpm mods:set` with a threshold key, or the 🎛️ row, then every session's next poll uses the value; a value below 1, above 100, or a notice value above the must value is refused and named.
9. given `pnpm mods:set hot <session id>` with no value, then it prints that session's 🔥 state; with `on` or `off` it flips it, for a `--bg` session too; red on a session id that does not exist.
10. given a throwaway session that holds an open orbit ask, a held file and a running background job, with an older handoff of another thread in the store, when its wind runs, then `op second-wind` is refused until the job resolves; after it, this wind's handoff is the one ingested, the older one is untouched, and the ask and phases survive; a session that wrote no handoff is refused and stays uncompacted.
