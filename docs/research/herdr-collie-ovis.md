## verdict

1. neither tool renders herdr-app mods on an iphone: mods draw native GPUI views through the `herdr`, `gpui-kit` and `gpui-base` host modules, and neither phone client has a GPUI renderer. Both repos were read at their shas on 2026-11-16 (proof in vector 5).
2. collie: **partly**. Its "tricks" are a separate JSON-parts UI contract (22 node kinds, a Hill for asks, an agent view per session). A mod's *data* can be re-emitted there, so the deck's asks and plans have a real path to the phone.
3. ovis: **no** for custom ui. It has the richest stock chat, approvals and plan view, plus herdr TUI pane tokens in its sidebar (TUI runtime only). The maintainer declined to render mods (#2769).
4. try ovis first if the goal is the best stock phone chat on herdr-app (herdr-core is a first-class runtime there). Try collie first if the goal is pushing his own deck onto the phone. Collie labels herdr-core experimental.
5. borrow from all three (all MIT). The most useful are collie's closed-parts renderer and Hill, ovis's pane-token mirror and typed socket RPC map, and shepherdr's "every feature has a mod side and a web side" manifest.

## 5. mobile: beyond a raw terminal, and the user's OWN herdr mods

**which of the four would have been the best base to start a custom herdr layout from, and why.** Shepherdr. This is an inference from the rows above.
- it is the only one of the three alternatives that is the same kind of artifact as zoo: a herdr-app layout made of mods.
- it already solves zoo's two structural gaps. Duplicated code across mods is handled by `core/` plus `bin/sync-shared`. "No phone" is handled by a web twin per feature, checked by `features.json` in CI. That twin is the only route in this research to his own custom ui on an iphone (vector 5).
- it has tests, its updates keep the user's own mods and layouts ([S/README.md L43, L84](https://github.com/eliasstravik/shepherdr/blob/abd5a0f1aa6faf2d0ee8d6559dc7f064fdae488e/README.md#L43-L84)), and it is MIT.
- collie and ovis are not layout bases; they are external clients whose patterns can be borrowed (vector 7).

**what moving off a zoo-derived base toward shepherdr would cost.** In broad terms, and all of this is inference; his own layout files were not read:
- **cheap:** his `x-herdr-*` mods already run on the same mod host API that shepherdr's mods use (`herdr`, `gpui-kit`, `gpui-base`). The panels themselves don't need rewriting.
- **moderate:** pull the logic shared between his mods into a `core/` with a sync step, and add `herdr-app check`, tests and the deploy discipline. This is a refactor, not a rewrite.
- **expensive:** a web twin for each mod he wants on the phone (deck, chat, sidebar) means a second renderer plus a Bun service. Shepherdr needed `web/` with 545 source files across the repo for its full set. The zoo-derived chat (`claude-chat`) would also be replaced or rewritten against shepherdr's chat mod.
- **advice:** take shepherdr's skeleton (sync-shared, features.json, the update and doctor discipline) without its opinions (Assistants, tasks, worktrees). Adopting shepherdr whole would replace his workflow rather than carry it.
